## 3 · Verified numbers

### Photo ID trajectory (benchmark: 916 queries, 186 AU species, fixed seed)
| Run | top-1 | top-3 |
|---|---|---|
| Raw baseline | 71.8% | 86.5% |
| + canonical key merge | 80.8% | 88.5% |
| + PCA whitening (harness) | 82.4% | 89.2% |
| **Shipped `PhotoID` on `index-v2`** | **82.4%** | **91.3%** |

Quote **82.4%** for both paths. The `80.2%` originally recorded here was measured
through a buggy label registry and is superseded — see §6, P1 (now resolved).

### Levers measured and ruled out
| Lever | Result |
|---|---|
| kNN label voting (unweighted, k=3…50) | 80.1% → 67.0% — hurts at every k |
| kNN voting (similarity / sim³ weighted) | 79.0% → 80.1% — still below 1-NN |
| Flip-TTA query embeddings | 80.5% — slightly negative |
| Per-species gallery cap 60 / 100 | 80.5% — neutral |
| Per-species gallery cap 40 | 77.5% — harmful |
| Linear classifier head (174-way) | 20.2% — far worse than retrieval |
| SigLIP2-400m fusion | 0.17 img/s → ~23 h per AU pass |
| DINOv2-large | 0.16 img/s → ~24 h per AU pass |

### Confidence bands (whitened score scale)
| Band | Threshold | Share | Precision |
|---|---|---|---|
| auto | ≥ 0.65 | 60.9% | 88.7% |
| confirm | 0.44 – 0.65 | 33.1% | 72.3% |
| unknown | < 0.44 | 6.0% | — |

**Precision peaks near 0.65 and FALLS above 0.75** — the legacy 0.80 threshold
selected the worst decile. No threshold reaches 95%; the encoder ceiling is 92.3%.

- Extraction: **11/11** previously-failing names resolve.

## 5 · Decisions taken, and why

1. **Report the conservative number** — *superseded 2026-09-19.* Originally: quote
   80.2% (shipped) over 82.4% (harness). There was only ever one number: the 2.2-point
   gap was a label-registry bug, so both paths are **82.4%**. See §6 P1.
2. **Structural grounding, not prompting.** The strict-prompt experiment proved an
   instruction does not bind a 1B model; `grounding.py` repairs output instead.
3. **Neutralise rather than delete.** Dropping a sentence containing an invented
   threshold also discarded the true claim; rewriting keeps the claim.
4. **Explicit region fallback.** `get_indicators()` now returns
   `region_fallback: true`, so UK/EU data is never passed off as Australian.
5. **Do not fabricate coverage.** Two web-research agents were instructed to record
   `not_found` rather than guess; both did, extensively.
6. **v1 index left untouched.** `index-v2` is additive; nothing overwrote the
   existing artifact.

## 6 · Open items, in priority order

### P0 — the 90% target (blocked on resources)
Options, all measured:
- **GPU + encoder fine-tuning.** The only real lever left. The repo's own earlier
  contrastive attempt failed (8.6% vs 74.6% baseline), so it needs a careful recipe —
  LoRA on attention with strong regularisation, evaluated on this benchmark.
- **Denser galleries.** The one lever *not* fully tested. A partial run was started:
  `holcus lanatus` went 50 → 125 images before the test was aborted. **That species'
  75 new images have no `sources.jsonl` sidecar entries** — either backfill them or
  delete those files. Re-embedding is then needed, and the benchmark re-run.
- Recommend: stay AU-scoped, ship top-3-confirm UI, treat `auto` as "higher
  confidence" not "safe to accept".

### ✅ P1 — RESOLVED 2026-09-19: the "2.2-point discrepancy" was a label-registry bug

The harness and the shipped path never measured the same function. `PhotoID.canonical()`
read `canon_map.get(key, alias.get(key, key))`, letting the legacy v1 `alias_map.json`
override canonical merges. Two entries reversed a merge by a trailing period:

```
alias["prosopis spp"] = "prosopis spp."   (canonical_map says the reverse)
alias["salix spp"]    = "salix spp."      (canonical_map says the reverse)
```

`index-v2/keys.json` stores **canonical** labels, so ground truth was rewritten one
way while predictions were stored the other way — a correct prediction scored as a
miss. `calibrate_bands.py` used the canonical definition (`measured.top1 = 0.8242`)
while the shipped measurement used the alias definition (0.8155).

**Fixed:** `resolve_label()` treats a label the index serves as its own fixed point;
`PhotoID.__init__` raises if any label resolves outside the index; regression tests
in `tests/test_label_registry.py`. Re-measured on all 916 queries:

| path | top-1 | top-3 |
|---|---|---|
| harness (`bench.py`, no collapse) | **0.8242** | 0.8919 |
| shipped `PhotoID` (collapse) | **0.8242** | 0.9127 |

Top-1 now agrees **exactly (delta 0.0000)**. Top-3 differs legitimately: `PhotoID`
collapses duplicate species in top-k, `bench.py` does not (809/916 queries repeat a
label in their raw top-3).

### ✅ P1 — RESOLVED 2026-09-19: text path had the same label fragmentation as vision
All 19 duplicate-key pairs in `data/vision/canonical_map.json` also existed in the
text DB as separate species (`curled dock` **and** `rumex crispus`, `creeping
thistle` **and** `cirsium arvense`, …), and the canonical map was wired only into
the vision scripts. **Twelve of the twenty pairs held different indicator data**,
so a farmer asking about "curled dock" and one asking about *Rumex crispus* got
different soil stories for the same weed. `get_indicators()` now resolves the
whole canonical group and **merges** their indicators rather than choosing a side
(the alias key is richer for 2 of 20 pairs, the canonical for 6, so either choice
would discard real rows).

Two traps worth remembering, both caught by tests:
- The merge was query-order **dependent** until the group was ordered with the
  canonical entry first; `cirsium spp` and `cirsium vulgare` define
  `General indicators` differently, so the answer still varied by the name typed.
- Identity must follow the **queried** key while only data merges. Taking the
  scientific name from the canonical lead relabelled "thistles" as *Cirsium
  vulgare* — a species claim the farmer never made.

### P1 — extractor quality (held-out eval now exists)
- **Held-out measurement built** (`tests/test_canonical_merge.py`). Querying
  `common_name_synonyms.json` proves nothing — it is a direct lookup and reports
  100% by construction. The honest test disables the curated map and asks whether
  fuzzy matching alone recovers the right species:
  **89/158 = 56.3%** (was 79/158 = 50.0% before the canonical merge).
- ✅ **Genus-bucket behaviour resolved 2026-09-19.** `docks and thistles` →
  `Curled dock, Cirsium spp` and `soursob` → `Oxalis spp.` are *correct*: no single
  species is implied by a plural/common vernacular. Matches are tagged
  `specificity: exact_species | genus_bucket | junk` and the answer discloses
  genus-level matches.
  **A promotion attempt was made and reverted.** Forcing a species to outrank a
  genus bucket picked the next candidate *by score*, which only shares the genus:
  `soursob` → *Oxalis acetosella* (a European wood-sorrel) and `rushes` →
  *Juncus tenuis*. Both are wrong for an Australian paddock and worse than the
  honest genus answer, so the rule is "label, never promote".
- Non-species keys sourced from the published training JSONL (`rushes excess`,
  `fumitory loam`, `astrebia spp`, `tripleurosper perforatum`, …) used to reach the
  runtime DB and create empty gallery dirs. Fixed at parse time via
  `scripts/junk_keys.py` + `SpeciesDB._sanitize()`; `scripts/cleanup_workspace.py`
  removes the directories they left behind.

### ✅ P1 — RESOLVED 2026-09-19: intent guard rail is now wired in
`scripts/intent.py` was written to decline management/advice requests and its own
module self-test reported "14/14 probes correct" — but **nothing imported it**, so
through the real entry point `"What herbicide should I use on lantana?"` still
returned `refused: False` and a lantana soil story. The probes exercised
`intent.classify()` directly and never `funnel.answer()`, so a dead guard rail
looked like a live one for a whole session.

**Fixed:** `answer()` classifies intent before extraction and returns
`decline_response()` with `refused: True`, `refused_reason: "management"`. The
deliberate precedence is preserved — an explicit indicator question still wins
("what does lime-loving capeweed indicate?" answers normally). `answer()` also now
returns `intent` and `refused_reason`, and **discloses region fallback** in the
response text (the `region_fallback` flag existed but was never surfaced, so UK/EU
data could be shown to an AU user silently).

Regression tests go through `answer()`, not the classifier:
`tests/test_funnel_behaviour.py` (8 checks).

### P2 — formatter
- The grounding pass is numeric-only. It does not catch *direction* errors
  (e.g. "favours drier ground" for a plant documented as "moist to moderately dry").
  **Attempted 2026-09-19 and correctly NOT shipped.** `scripts/claim_verify.py`
  implements the check, but measured against the 40 reviewed-faithful answers it
  reports conflicts in **25/40 = 62.5%**, almost all false positives — it would
  delete true claims. `repair_direction()` now raises unless `allow_unsafe=True`,
  the funnel does not import it, and a test pins the 62.5% figure.
  Root cause (diagnosed, see the module docstring): the lexicon was built from
  keyword frequency rather than corpus semantics — "fresh" means low *salinity*
  here, not "moist"; "calcareous" is a soil-type word, not a pH equivalent of
  "alkaline"; and "moderately dry"/"dry" both match in one phrase, blurring the
  interval. Shippable route: derive the lexicon from the indicator values
  themselves, use longest-match tokenisation, keep domains free of cross-domain
  terms, and label real direction errors to measure recall.
- Temperature 0.3 gives run-to-run variation; consider lowering for factual output.

### P2 — data
- 51 species still have no indicators in any region.
- 2,040 of 2,324 species have no real vernacular name; the 188 AU species are the
  priority and are now partly covered by synonyms, but coverage is not exhaustive.
- ✅ **Mojibake fixed 2026-09-19** (`scripts/repair_mojibake.py`). The 14 entries
  were two distinct artefacts: soft hyphens (U+00AD) left at PDF line breaks
  (`compac­tion` → `compaction`) and PUA glyphs (U+F052/U+F0B2) where a symbol
  font failed to map, always at field boundaries (`acidic soil ␒ high fertility`
  → `acidic soil / high fertility`). 21 strings repaired, 0 artefacts remain.
  En/em dashes, ², µ and ≥ were deliberately preserved — a naive "non-ASCII sweep"
  would have destroyed real typography.

## 7 · Warnings for the next session

- **Do not trust the repo's 80.9% top-1** in isolation. It is reproducible only with
  canonicalisation on a well-formed split; the raw-key number is 71.8%.
- **Do not quote 80.2% — it is superseded.** It came from a buggy label registry.
  The shipped path is **82.4% top-1**, identical to the harness. See §6 P1.
- **Never let an alias map rewrite a label the index serves.** That one bug created a
  phantom 2.2-point "accuracy gap" that survived a whole session. `resolve_label()`
  now enforces the fixed-point property and `PhotoID.__init__` raises on violation.
- **Empty directories are not evidence of missing sidecars.** 49 species dirs have no
  images at all (real data gaps); 8 more were junk keys and are now removed. An audit
  that treats "no `sources.jsonl`" as "missing sidecar" will report ~57 false positives.
- **Do not reintroduce `AUTO_CONF = 0.80`.** It is wrong for the whitened scale and
  selects the worst decile.
- **Phantom-species bug is fixed but the mechanism is worth remembering:**
  a DB common name containing parentheses
  (`Prickly Pear (Cane Cactus / Eve's Pin Cactus) (austrocylindropuntia spp)`) made
  the old regex extract `Cane Cactus` as a species, creating a key called
  `dense infestations` that shadowed real rows. Any future name-extraction change
  should be tested against parenthetical common names.
- **The gallery is local-only and gitignored.** `data/vision/emb/` (embedding cache)
  is also gitignored — a fresh clone must re-embed before benchmarking.
- **Source access:** `dpi.nsw.gov.au`, `pir.sa.gov.au`, `agriculture.vic.gov.au`,
  `daf.qld.gov.au`, `grdc.com.au` return HTTP 403 to automated fetch. Working:
  `weeds.dpi.nsw.gov.au`, `weeds.org.au`, `herbiguide.com.au`,
  `keyserver.lucidcentral.org`, `landscape.sa.gov.au`, `awri.com.au`.
  A quote-to-source verifier is at `data/research/_tools/verify2.py`.

page returns 403 (bot protection), and `/v1/observations?taxon_id=…` works but
would need paging through 265,470 observations for *Achillea millefolium* to find
8 ids.

non-species artefacts** created when the acquisition puller probed iNaturalist for
junk keys parsed out of the training JSONL. Those 8 are removed
(`scripts/cleanup_workspace.py`); the remaining **49 are genuine data gaps** and
are deliberately preserved. Species dirs: 2,231 → 2,223.
