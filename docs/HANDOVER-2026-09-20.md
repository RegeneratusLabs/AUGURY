## 2 · The headline: four real bugs found, all of which broke the app

These were found by building the verification that did not exist before. Each one
would have shipped a broken app:

### 2.1 `ManifestDigest` hex-encoded the manifest instead of hashing it
`artifacts/ArtifactManifest.kt` called `Sha256.hex(...)` where it meant a digest.
`Sha256.hex()` only *encodes bytes as hex* — so the "generation" was 24 KB of
hex-encoded JSON, not a 64-char SHA-256. **The app rejected every real manifest**,
including its own published one. `Sha256.of()` was added and the call site fixed.
This is why `ProtocolGateTest accepts the shipped manifest` now passes.

### 2.2 `Npy` refused Fortran-ordered arrays — and the shipped `W` is Fortran-ordered
`data/vision/index-v3/pca_whiten.npz` stores `W` `(768,384)` **F-contiguous**.
The reader threw `VisionContractException`. **The photo path could never load an
index on any device.** Fixed by transposing to C order on read.

### 2.3 …and my first fix transposed it the wrong way
The inverse mapping `(i % rows) * cols + i / rows` is wrong; it produced a
whitened query **0.28 away** from the Python reference instead of matching to
`3e-8`. The correct mapping is `(i % cols) * rows + i / cols`. This is recorded in
the code comment because it is a genuinely easy mistake to repeat.

### 2.4 `Json.canonical` sorted keys by UTF-16 code unit, not code point
CPython's `json.dumps(sort_keys=True)` orders by **code point**; Kotlin's
`String.sorted()` orders by UTF-16 code unit. They diverge for supplementary
characters, so a publisher manifest containing one would be **rejected as a digest
mismatch**. Fail-closed, but it broke the byte-compatibility guarantee the whole
manifest scheme rests on. Fixed with a code-point comparator + regression test.

> **The pattern worth carrying:** three of these four were invisible to a
> "does it compile / does the happy path work" test. They only surfaced because
> the vision path was checked against *recorded Python ground truth*, and the
> artifact pipeline was checked against *the manifest it actually ships*.

### 3.2 Artifact pipeline — `artifacts/` (2,811 lines, 94 tests)

Manifest fetch + parse + self-digest verification, HTTP `Range`-resumable
download, streaming SHA-256, a generation store with stage-verify-promote and
rollback, Wi-Fi-only enforcement, and tar.gz unpacking.

The security invariants are enforced **by control flow, not discipline**
(`ArtifactManager`): a hash mismatch is unreachable from the promotion path
because it deletes the partial and throws first. Tests cover corrupted bodies,
truncation, resume correctness, `..`/absolute/backslash/drive-letter/symlink
traversal, and a downgraded generation.

### 3.3 Vision path — `vision/` (1,932 lines)

`Preprocessor` → `OnnxEncoder` (ORT Mobile) → L2 → PCA-whiten → L2 → `KnnIndex`
(inner product + canonical collapse) → `Bands` (from the manifest).

**Verified against recorded Python ground truth** by
`app/src/test/java/.../vision/VisionParityTest.kt` (8 tests) using fixtures from
`tools/emit_vision_fixtures.py`:

| Check | Result |
|---|---|
| preprocessing vs the fixture reference | within the recorded kernel delta (max 4 LSB) |
| the two bicubic kernels' CLS cosine | **0.99998** |
| top-3 under both kernels | **identical species and scores** |
| L2 → PCA-whiten → L2 vs Python | **matches** |
| kNN top-3 (keys, canonical, scores) vs Python | **matches** |

### Gotchas for the next publish
- **`HF_TOKEN` must be exported**, and `HF_HOME` must point somewhere writable.
  `$HOME` is read-only here, and redirecting `HF_HOME` also redirects the *token*
  lookup — so the token has to be passed explicitly:
  ```bash
  export HF_HOME="$PWD/.dsh-runtime/hf-home" HF_HUB_DISABLE_XET=1
  export HF_TOKEN="$(cat ~/.cache/huggingface/token | tr -d '\n')"
  ```
- **Xet must stay disabled** (`HF_HUB_DISABLE_XET=1`): its staging dir lands in
  `~/.cache/huggingface/xet/…`, which is read-only here.
- **`build_ondevice_bundle.py` rewrites `augury-ondevice.json`** with a fresh
  `generated` timestamp *every run*, so its sha256 changes. Two consequences:
  re-upload the facts file whenever you regenerate the manifest, and **do not**
  apply a hand-edited JSON parser after the fact. The clean procedure is:
  regenerate → upload facts → upload manifest → pin the revisions → regenerate →
  upload the manifest again.

## 5 · ⚠️ The one thing that has NOT happened: nobody has seen the app run

**This host cannot run the app, and no download can fix it.** Recorded precisely:

- `/dev/kvm` is absent.
- Android's x86_64 emulator **hard-requires** hardware acceleration and refuses
  to start: `ERROR | x86_64 emulation currently requires hardware acceleration!`
  / `CPU acceleration status: /dev/kvm is not found`.
- The AVD (`augury`), the system image (`android-34/default/x86_64`) and the
  emulator binary are **already installed** — the blocker is not missing files.
- The TCG fallback documented in the 09-19 handover (running the emulator's QEMU
  directly via `scripts/run-qemu-direct.sh`) **no longer works**: the captured
  vector is rejected by the standalone QEMU binary (`unknown option: -device`),
  and re-capturing it fails because the wrapper exits before printing the
  `Concatenated QEMU options:` line on this host.

**What this means concretely.** Verified here: the code compiles, 162 tests pass,
the APK packages with both `.so`s, and the vision *maths* is byte-comparable to
Python. **Not** verified here: that the app renders, that `libonnxruntime.so` and
`libaugury_llama.so` load on a device, that `BitmapFactory` decode feeds the
preprocessor correctly, that 1.06 GB downloads successfully, or that an answer
takes the documented ~1.7 s on a phone.

**A real arm64 device is the only way to close this.** Install
`app/build/outputs/apk/debug/app-arm64-v8a-debug.apk` (48 MB), and expect the
first run to want ~1.06 GB of Wi-Fi.

> **A note on `docs/ui/mockup.html`:** it is an accurate rendering of the Compose
> sources, and it is the best available visual, but it is **not** evidence that
> the app works. Treat it as design documentation, not as a test result.

## 6 · Design decisions worth not re-litigating

1. **`DemoGateway` is not a production path.** `AppGraph.gateway()` constructs
   `AuguryGatewayImpl` and *fails loudly* if it cannot. An earlier draft fell back
   to `DemoGateway`, which reads the species DB from a **repo path** that exists
   on no phone — it would have shipped an app with a permanently empty picker.
   `DemoGateway` now exists only for tests and previews.
2. **No `material-icons-extended`.** It was the largest dex contributor; the UI
   draws its own glyphs. Removing it cut ~7 MB.
3. **ABI splits are on.** A fat APK is 90 MB; `arm64-v8a` alone is 48 MB. x86_64
   exists only for the emulator, which cannot run here anyway.
4. **The spike harness is retained but disabled.** `spike/SpikeActivity.kt` is
   still built (and its five strings are still in `strings.xml` on purpose) so it
   stays runnable via `adb shell am start` for on-device engine timing. It is no
   longer the launcher and is not exported.
5. **The UI depends on an interface, not on the pipeline.** That is what let the
   screens be written and compiled before the downloader and vision code landed,
   and it is why the six screens can be rendered from `DemoGateway` with no
   network, no model and no native library.

## 7 · Known-open items, in priority order

### P0 — real-device test
The only way to close §5. Sideload the arm64 APK, confirm both `.so`s load, time
an answer, and watch memory (the encoder and the GGUF must never be resident
together — `AuguryGatewayImpl.generateDraft` opens and closes the engine around a
single call for exactly this reason).

### P1 — the formatter model is never actually used yet
`generateDraft()` is wired and will call `LlamaEngine`, but it has **not been
exercised on a device**, and the prompt it builds has not been compared to
`scripts/augury_funnel.py`'s. Until then every story is the deterministic
template, which is faithful but not the product's full output. This also means
the grounding-repair path (`StoryScreen`'s "CORRECTED" card) is untested against
a real model draft.

### P1 — `Docs/vision-kotlin-verification.md` was never written
The fixture generator (`tools/emit_vision_fixtures.py`) and the parity tests
exist and pass; the written record of *what was run and what remains unverified*
does not. `VisionParityTest`'s class comment documents the method — promote that
into the doc.

### P2 — species display names on the photo screen
`AuguryGatewayImpl.identify` returns the canonical key as `scientificName` and
leaves `commonName` null, so the confirm card shows `cirsium vulgare` rather than
"Spear thistle". The picker shows proper common names. Fixing this needs a public
display accessor on `SpeciesStore` (its `species` map is private).

### P2 — upload the manifest one final time
The last manifest upload (`25449234f781…`) is the one whose revision pins are
correct; the facts file it references is at `3fb4801eb7f7`. If anyone re-runs
`build_ondevice_bundle.py` without re-uploading, the pins go stale — see §4's
procedure.

### P3 — release build is unsigned and unminified
`release` has `isDebuggable = true` and `isMinifyEnabled = false`, left over from
the spike. A shippable APK needs a keystore, `isDebuggable = false`, and R8.

## 8 · Hard constraints — unchanged, and now partly enforced by tests

The 09-19 handover's §8 list still stands in full. This session added enforcement:

| Constraint | Now enforced by |
|---|---|
| Never hard-code a threshold/count/dimension/version | `VisionParityTest.the shipped index matches the manifest`; bands read from manifest |
| Never reintroduce `AUTO_CONF = 0.80` | `Bands.LEGACY_*` kept as explicitly-named constants never used as live thresholds; `tests/test_band_config.py` |
| Always show top-3 | `VisionPipeline.init` **refuses to construct** if the index cannot serve 3 distinct species; `VisionParityTest` asserts it |
| Grounding pass is mandatory | `AuguryGatewayImpl.story` routes every draft through `Grounding.repair` |
| A truncated/hash-mismatched artifact never loads | `ArtifactManagerTest` (truncation, corruption, resume) |
| Partial downloads are never promoted | `ArtifactManager` control flow + `GenerationStoreTest` |
| Encoder and GGUF never co-resident | `generateDraft` scopes the engine to one call |
| Respect the protocol gate | `ProtocolGate` + `VisionSettings.requireSupported()`; `ProtocolGateTest` (13 tests) |
